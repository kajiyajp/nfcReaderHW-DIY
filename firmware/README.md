# ファームウェア

> 作成：2026-11-16 ／ 目的：NFC 読み取り機のファームウェアの置き場所と使い方

## xiao_rp2040_pn532_hid（市販部品で作る USB キーボード型の読み取り機）

このリポの基本の構成。**XIAO RP2040** と市販の **PN532 モジュール** で読み取り機を作る（自作基板は 2026-11-20 に凍結。`archive/pcb/`）。
USB に挿すとキーボードとして認識され、社員証をかざすと **UID（16 進）と Enter** を打ち込む。
MeetingLog の確認端末（`/kiosk`。キーボード入力方式）にそのまま使える。ドライバーも PC 側の設定も要らない。

### 部品

| 部品 | 例 | メモ |
|---|---|---|
| マイコン | Seeed XIAO RP2040（手持ち） | USB キーボード（HID）になれる。XIAO ESP32C6 は USB キーボードになれないので使わない |
| NFC | PN532 NFC RFID モジュール V3（購入したもの：Amazon ASIN B0H6ZYCJVQ、998 円。同等品 B0GSBFKC8P） | 約 40×43mm。13.56MHz、ISO 14443A（NTAG・MIFARE）、FeliCa。読み取り距離 4〜6cm |
| ケース | `case/`（3D プリント） | 組み立て方は `case/README.md` |
| 線 | ジャンパ線 4 本（IRQ もつなぐなら 5 本） | |

### 配線（4 本。IRQ は任意）

| PN532 モジュール | XIAO RP2040 |
|---|---|
| VCC | 3V3（5V でも動く。下の説明を読む） |
| GND | GND |
| SDA | D4（SDA） |
| SCL | D5（SCL） |
| IRQ（任意） | D2 |

- PN532 モジュールの小さなスイッチを **I2C** にする（V3 は通常 SW1 = ON、SW2 = OFF。基板の表示で確かめる）
- 電源（VCC）は XIAO の **3V3** から取る。信号の電圧がそろうので、測らなくても XIAO（3.3V まで）に安全。3V3 でも 5V でも、社員証を読めることを確かめた（2026-11-19）
  - 5V でも動く。購入したモジュール（B0H6ZYCJVQ）は、VCC が 5V でも SDA・SCL は約 2.7V だった
  - **別のモジュールを 5V で使うときは、先に SDA・SCL を XIAO から外したまま電圧をテスタで測る。** 3.6V 以下ならつないでよい。4V 以上なら 5V はやめて 3V3 にする（XIAO を傷める）
- IRQ は無くても動く（Adafruit PN532 1.3.3 は I2C の応答待ちに IRQ を使わない。古い 1.2 系を使うときだけ要る）

### 書き込み（最初の 1 回）

1. Arduino IDE の「ボードマネージャ」で **Raspberry Pi Pico/RP2040/RP2350**（Earle F. Philhower 版）を入れる
   （ボードマネージャの追加 URL：`https://github.com/earlephilhower/arduino-pico/releases/download/global/package_rp2040_index.json`）
2. 「ライブラリマネージャ」で **Adafruit PN532** を入れる（Adafruit BusIO も一緒に入れるか聞かれたら入れる）
3. ボードを **Seeed XIAO RP2040** にする。USB Stack は既定の **Pico SDK** のまま
4. `xiao_rp2040_pn532_hid.ino` を開き、XIAO の **B（BOOT）ボタンを押しながら USB を挿す** → ポートを選んで書き込む
   （2 回目以降はそのまま書き込める）

### 確認した内容

- **コンパイル：** arduino-cli で `rp2040:rp2040:seeed_xiao_rp2040`（ボード定義 rp2040 6.3.2、Adafruit PN532 1.3.3、Adafruit BusIO 1.17.0）向けに通る（フラッシュ 3%）
- **実機（2026-11-19）：** XIAO RP2040 ＋ PN532 モジュール V3（B0H6ZYCJVQ）に書き込み、NTAG215 の社員証をかざして確かめた
  - VCC が 5V のとき：10 回かざして、テキストエディタに 14 桁の番号と改行が 10 行入った（取りこぼし・重複なし）
  - VCC が 3V3 のとき：15 回かざして、同じく 15 行入った。シリアルにも `Sent: …（7 bytes）` と出た
  - アンテナにぴったり置いたまま 25 秒：読め続けて（5 秒ごとに `reads=23/46`）、再送はしなかった
  - アンテナに触れるくらいまで近づけて 2〜3 秒置き、離す、を 30 回：29 回は 1 行だけ入った。1 回だけ 2 行入った（離す途中の 0.66 秒の途切れ。このあと判定を 0.6 秒から 1.5 秒に延ばした）
  - 判定を 1.5 秒にしたあと、同じやり方で 10 回：シリアルの記録では 10 回とも 1 回ずつの送信だった

### ライブラリの不具合を避けている（Adafruit PN532 1.3.3）

- ライブラリの `setPassiveActivationRetries()` は、命令を送ったあと **PN532 の返事を読まずに終わる**。I2C では返事が PN532 に残り、次の命令から通信がかみ合わなくなって、PN532 が応答しなくなる（SCL を 0V に押さえたまま固まることもある）
- このスケッチは同じ命令を自前で送り、返事を読み捨てている（スケッチ内の `setPassiveActivationRetries()`）。ライブラリの同名の関数（`nfc.setPassiveActivationRetries()`）は呼ばないこと
- PN532 が固まると、XIAO に書き込み直しても戻らない（PN532 の電源が切れないため）。**USB を抜いて 5 秒待ち、挿し直す**
- **ファームウェアを書き込んだ直後も、同じように固まることがある**（XIAO だけが再起動し、PN532 が通信の途中で取り残される。シリアルに `PN532 not found (SDA=1 SCL=0)` と出続ける）。書き込んだあとは USB を挿し直す。ふだんは XIAO と PN532 の電源が同時に入るので起きない

### カードを近づけすぎると番号が 2 回入る問題を避けている

- **起きていたこと：** カードをアンテナに触れるくらいまで近づけて置くと、最初に 1 回読めたあと、置いている間はまったく読めなかった。そのため「離した」と誤って判定し、離すときにもう一度読めて、番号が 2 回入った。40mm くらい離してかざすと起きない
- **原因：** 近すぎると、PN532 の標準の受信の感度（38dB）ではカードの返事を受け取れない。ぴったり置いた状態で設定を変えて測ると、標準は 10 回中 0 回、感度を 18〜33dB に下げると 10 回中 10 回読めた（送信を少し弱めても読めた）
- **対策：** カードを探すたびに、受信の感度を「標準（38dB、離れたカード用）」と「23dB（近いカード用）」で交互に切り替える（スケッチ内の `setRxGain()`）。近くても遠くても 2 回に 1 回は読めるので、置いている間も「かざしている」と分かる
- 「離した」とみなす時間（`RELEASE_MS`）は 1.5 秒。同じカードをもう一度入力したいときは、1.5 秒以上離してからかざす
- 探すたびに電波を一度切っている（`rfFieldOff()`）。これだけでは直らなかったが、上の測定はこの手順で行ったので、そのままにしている

### 動作確認

1. メモ帳を開いてカーソルを置き、社員証（NTAG シール）をかざす
2. `04A1B2C3D4E5F6` のような 14 桁（NTAG は 7 バイト）と改行が入れば OK。MIFARE Classic のカードは 8 桁
3. かざしたままにしても連打しない。いったん離して（1.5 秒以上）またかざすと、もう一度送る
4. 入らないとき：Arduino IDE のシリアルモニタ（115200bps）を開くと、状態が分かる
   - `PN532 not found`：配線・スイッチの間違い。線の挿し込みが浅いだけのこともある
   - `Waiting for a card... PN532 OK reads=0/46`（5 秒ごと）：PN532 は動いている。`reads` は、この 5 秒で「読めた回数/探した回数」。カードを置いたままなら半分くらいになる
   - `held: gap=…ms`：かざしている途中で 0.25 秒以上読めない時間があった（再送はしていない）
   - `Sent: … SAME CARD gap=…ms`：同じカードをもう一度送った。`gap` は前に読めてからの時間。かざしたままなのにこれが出るときは、`RELEASE_MS` を延ばす
   - `Waiting for a card... PN532 NOT RESPONDING`：PN532 が固まっている。USB を抜いて 5 秒待ち、挿し直す
   - `Sent: ...`：読めている

### LED の表示（かざした人への反応）

XIAO RP2040 の基板上の RGB LED（2 つのボタンの間）で、読み取り機の状態を示す。

| LED | 意味 |
|---|---|
| 青をごく弱く点灯 | 待機中（電源が入っていて、PN532 も動いている） |
| 緑 1 秒 | 読めて、番号を送った |
| 黄 | 同じカードをまた読んだが、送らなかった（緑のあと置いたままの間、または離して 1.5 秒以内のかざし直し） |
| 赤 0.2 秒の点滅 | PN532 が見つからない・応答しない（配線の外れ、PN532 の固まり）。USB を抜いて 5 秒待ち、挿し直す |

- **社員証が登録済みかどうかは、LED では分からない。** 読み取り機は番号を打ち込むだけで、PC から返事を受け取らない。登録済みかどうかは確認端末の画面に出る
- LED は RP2040 の PIO で直接動かしているので、追加のライブラリは要らない
- 色・明るさ・時間は、スケッチの `COLOR_…` と `LED_…_MS` で変える。圧電ブザーを足すときは、`feedback()` の中に音を足す
- 2026-11-19 に実機で、表のとおりに光ることを目で見て確かめた。赤の点滅（PN532 のエラー）は、わざと起こしての確認はしていない

### 場所の番号（どの読み取り機でかざしたか）

読み取り機ごとに **1〜4 桁の数字** を持たせると、かざしたときに、社員証の番号の前に付けて打ち込む。

| 設定 | 打ち込む文字 |
|---|---|
| 場所なし（最初の状態） | `04A1B2C3D4E5F6` |
| 場所 12 | `L12U04A1B2C3D4E5F6` |

- **設定の方法：** PC につなぎ、Arduino IDE のシリアルモニタ（115200bps、改行あり）から打つ

  | 打つ文字 | 動き |
  |---|---|
  | `LOC 12` | 場所を 12 にする（`LOC=12` でも同じ） |
  | `LOC OFF` | 場所をなしにする |
  | `LOC` | いまの設定を表示する |

- 番号は XIAO のフラッシュに保存する。電源を切っても残る。起動のときにも、いまの設定をシリアルに表示する
- `012` と `12` は別の番号として扱う（打ったとおりに保存する）
- 区切りに英大文字（`L`・`U`）を使うのは、記号だとキーボードの配列や日本語入力で別の文字に変わるため
- MeetingLog の確認端末は、この形を「場所」と「社員証の番号」に分けて受け取る。社員証の登録は場所によらない（どの読み取り機でかざしても同じ人）
- 2026-11-19 に実機で、設定・表示・誤った入力の断り（5 桁、数字以外）が動くことを確かめた。場所 12 に設定してかざし、
  MeetingLog の試験用の確認端末に「場所 12」での確認として記録されることも確かめた。USB を挿し直したあとも、番号（12）が残っていることを確かめた

### MeetingLog の確認端末で使う

- 確認端末の PC に挿し、確認端末の画面（`/kiosk`）を開いたままにする。あとは MeetingLog の `docs/nfc-card.md`「事務所の確認端末」の手順どおり（社員証の登録 → かざして確認）
- 番号は **16 進 14 桁（NTAG）** で入る。ほかの読み取り機（10 進で出すものなど）から乗り換えたときは、端末の番号を登録し直す
- 0〜9 と A〜F だけを送るので、PC のキーボード配列（日本語・英語）が違っても同じ文字が入る
- **PC の日本語入力（IME）はオフにしておく。** オンだと番号が全角（`０４Ａ１…`）で入り、Enter は変換の確定に使われて送信されない（2026-11-19 に確認。続けてかざすと番号がつながって入る）

### 注意

- PN532 モジュール（市販の開発用基板）には技適の表示がない。社内の常設機器として使うかは、市販のキーボード型の読み取り機と比べて決める
- 社員証の UID はコピーできるカードもある。確認端末は「読んだことの記録」用で、見られるのは配信済みの要約だけなので、MeetingLog の安全の考え方（`docs/nfc-card.md`「安全について」）の範囲で使う
