# ファームウェア

> 作成：2026-11-16 ／ 目的：NFC 読み取り機のファームウェアの置き場所と使い方

## xiao_rp2040_pn532_hid（市販部品で作る USB キーボード型の読み取り機）

自作基板を発注する前に、手持ちの **XIAO RP2040** と市販の **PN532 モジュール** で、同じ仕組みの読み取り機を作る。
USB に挿すとキーボードとして認識され、社員証をかざすと **UID（16 進）と Enter** を打ち込む。
MeetingLog の確認端末（`/kiosk`。キーボード入力方式）にそのまま使える。ドライバーも PC 側の設定も要らない。

### 部品

| 部品 | 例 | メモ |
|---|---|---|
| マイコン | Seeed XIAO RP2040（手持ち） | USB キーボード（HID）になれる。XIAO ESP32C6 は USB キーボードになれないので使わない |
| NFC | PN532 NFC RFID モジュール V3（購入したもの：Amazon ASIN B0H6ZYCJVQ、998 円。同等品 B0GSBFKC8P） | 約 40×43mm。13.56MHz、ISO 14443A（NTAG・MIFARE）、FeliCa。読み取り距離 4〜6cm |
| ケース | `case/`（3D プリント） | 組み立て方は `case/README.md` |
| 線 | ジャンパ線 4 本（IRQ もつなぐなら 5 本） | |

### 配線（4 本。IRQ は任意）

| PN532 モジュール | XIAO RP2040 |
|---|---|
| VCC | 3V3 |
| GND | GND |
| SDA | D4（SDA） |
| SCL | D5（SCL） |
| IRQ（任意） | D2 |

- PN532 モジュールの小さなスイッチを **I2C** にする（V3 は通常 SW1 = ON、SW2 = OFF。基板の表示で確かめる）
- 電源は XIAO の 3V3 から取る（5V から取るより信号の電圧がそろって安全）
- IRQ は無くても動く（Adafruit PN532 1.3.3 は I2C の応答待ちに IRQ を使わない。古い 1.2 系を使うときだけ要る）

### 書き込み（最初の 1 回）

1. Arduino IDE の「ボードマネージャ」で **Raspberry Pi Pico/RP2040/RP2350**（Earle F. Philhower 版）を入れる
   （ボードマネージャの追加 URL：`https://github.com/earlephilhower/arduino-pico/releases/download/global/package_rp2040_index.json`）
2. 「ライブラリマネージャ」で **Adafruit PN532** を入れる（Adafruit BusIO も一緒に入れるか聞かれたら入れる）
3. ボードを **Seeed XIAO RP2040** にする。USB Stack は既定の **Pico SDK** のまま
4. `xiao_rp2040_pn532_hid.ino` を開き、XIAO の **B（BOOT）ボタンを押しながら USB を挿す** → ポートを選んで書き込む
   （2 回目以降はそのまま書き込める）

### コンパイルの確認

- arduino-cli で `rp2040:rp2040:seeed_xiao_rp2040`（ボード定義 rp2040 6.3.2、Adafruit PN532 1.3.3、Adafruit BusIO 1.17.0）向けにコンパイルが通ることを確認済み（2026-11-16。フラッシュ 3%）。**実機（XIAO＋PN532 にカードをかざす）ではまだ試していない**

### 動作確認

1. メモ帳を開いてカーソルを置き、社員証（NTAG シール）をかざす
2. `04A1B2C3D4E5F6` のような 14 桁（NTAG は 7 バイト）と改行が入れば OK。MIFARE Classic のカードは 8 桁
3. かざしたままにしても連打しない。いったん離して（0.6 秒以上）またかざすと、もう一度送る
4. 入らないとき：Arduino IDE のシリアルモニタ（115200bps）を開くと、`PN532 not found`（配線・スイッチの間違い）か `Sent: ...`（読めている）かが分かる

### MeetingLog の確認端末で使う

- 確認端末の PC に挿し、確認端末の画面（`/kiosk`）を開いたままにする。あとは MeetingLog の `docs/nfc-card.md`「事務所の確認端末」の手順どおり（社員証の登録 → かざして確認）
- 番号は **16 進 14 桁（NTAG）** で入る。ほかの読み取り機（10 進で出すものなど）から乗り換えたときは、端末の番号を登録し直す
- 0〜9 と A〜F だけを送るので、PC のキーボード配列（日本語・英語）が違っても同じ文字が入る

### 注意

- PN532 モジュール（市販の開発用基板）には技適の表示がない。社内の常設機器として使うかは、市販のキーボード型の読み取り機と比べて決める
- 社員証の UID はコピーできるカードもある。確認端末は「読んだことの記録」用で、見られるのは配信済みの要約だけなので、MeetingLog の安全の考え方（`docs/nfc-card.md`「安全について」）の範囲で使う
